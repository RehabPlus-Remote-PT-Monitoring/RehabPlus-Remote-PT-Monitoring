# Movement replay: skeleton recording therapists can watch

Date: 2026-11-15. Option 2 of "let therapists validate the exercise":
no video. The app saves the pose points it already tracks, and the dashboard
replays them as a moving stick figure with each rep's verdict on the timeline.

## 1. What is recorded (and what is not)

- Recorded: for each analysed frame, the 33 ML Kit landmarks as normalised
  2D positions (0-1 of the upright image) plus each one's confidence, the
  exercise's measured joint angle, and the time since the session started.
  Also the rep/hold events the app already decides (counted / rejected with
  the reason the patient saw).
- Never recorded: camera images, video, audio, the room, the face. The points
  are not a picture of the person.
- Down-sampled to at most 10 frames per second, capped at 10 minutes per
  session (longer sessions keep the first 10 minutes and say so).
- Patients can turn it off: Settings > "Save movement replays for my
  therapist" (default on, phone-only preference). Off = no replay written,
  sessions save as before.
- Legal: privacy policy section 3 and the terms describe the replay;
  `LegalInfo.version` moves to `2026-11-15`, so every patient sees the
  consent screen again (the dashboard's `LEGAL_CONSENT_VERSION` moves with it).

## 2. Firestore layout

Under the existing session: `patients/{uid}/sessions/{sessionId}/replay/{docId}`.
The session doc id is generated by the app; the replay batch is written right
after the session (rules use `existsAfter` on the session).

`replay/meta`:

| Field | Type | Notes |
| --- | --- | --- |
| `version` | int | Format version, `1` |
| `fps` | int | Recorded frame rate (≤ 10) |
| `frameCount` | int | 0–6000 |
| `chunkCount` | int | 1–20 |
| `durationMs` | int | Time of the last frame |
| `truncated` | bool | The session ran past the 10-minute cap |
| `aspect` | number | Upright image width / height (0.2–5) |
| `mirrored` | bool | The patient saw a mirrored skeleton (front camera); the dashboard draws the same way |
| `angleLabel` | string ≤ 60 | What the angle measures, e.g. "Knee angle" |
| `events` | array of maps | `{t: int ms, kind: 'counted' \| 'rejected' \| 'hold', note: string ≤ 120}`, at most 200 |
| `createdAt` | timestamp | Server time |

`replay/c000` … `replay/c019` (chunk docs, 300 frames each, the last may be shorter):

| Field | Type | Notes |
| --- | --- | --- |
| `index` | int | 0–19, matches the doc id |
| `firstFrame` | int | Index of its first frame |
| `frames` | int | 1–300 |
| `data` | bytes | `frames` × 171 bytes, little-endian (below); ≤ 51,300 bytes |

Frame record, 171 bytes:
- `uint32` t: ms since the session started
- `uint16` angle in tenths of a degree (`0xFFFF` = not measured this frame)
- 33 × (`uint16` x × 10000, `uint16` y × 10000, `uint8` confidence × 255),
  in ML Kit's `PoseLandmarkType` order. A landmark the model didn't return is
  x = y = `0xFFFF`, confidence 0. A frame with no pose at all has every
  landmark missing (the dashboard shows "patient out of frame").

Size: ~1.7 KB per second of exercise (~100 KB per minute), ≤ ~1 MB per session.

The session doc gets an optional `hasReplay: true` so the dashboard only shows
"Replay" where one exists.

## 3. Rules

```
match /sessions/{sessionId}/replay/{docId} {
  allow read: if isSelf(patientId) || caresFor(patientId);
  allow create: if isPatient(patientId) && validReplayDoc(docId, request.resource.data);
  allow update, delete: if false;   // append-only, like sessions
}
```
`validReplayDoc`: `meta` with exactly the fields above, types and bounds
checked, `createdAt == request.time`; or `c000`–`c019` with `index` matching
the id, `frames` 1–300, `firstFrame == index * 300`, `data` bytes with size
`frames * 171`. Sessions also accept the optional `hasReplay` bool.

## 4. App (camera/monitoring first)

- `lib/services/replay_recorder.dart` (pure, unit-tested): `add(tMs,
  landmarks, angle)` with the 10 fps down-sample and the cap, `event(...)`,
  and `encode()` -> meta map + chunk byte lists. `decode` lives in tests to
  prove the byte layout round-trips.
- `PoseDetectorScreen` feeds it from the frame loop (normalised by the same
  upright image size the painter uses) and from the counted / rejected / hold
  paths. `_saveSession` saves the session exactly as today (plus
  `hasReplay`), THEN writes the replay docs in a second batch through
  `SessionStorage`. A refused or failed replay is logged and never loses the
  session (the dashboard then says "No replay available"). Firestore's
  offline queue sends both in order.
- Settings toggle; legal text + version bump.

## 5. Dashboard (web/messaging)

- Sessions list on the patient page: "Replay" link when `hasReplay`.
- `GET /patients/{uid}/sessions/{sessionId}/replay` (admin, or the patient's
  therapist; others 404): reads meta + chunks (server validates ids and sizes),
  page with a canvas player: play/pause, speed 0.5×/1×/2×, scrubber with event
  markers (green counted, red rejected with the reason), current angle, the
  session's summary beside it, "out of frame" when no pose.
- Decoder and drawing maths in a Vite module, unit-tested with vitest.
- Light and dark theme, phone width.
